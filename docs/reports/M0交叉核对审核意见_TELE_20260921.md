## 二、CODE 报告的 4 处精度修正（不推翻结论）

1. **"迁移=CMake 加 120a"不准确**：基线顶层 CMakeLists L8-9 `if(NOT DEFINED CMAKE_CUDA_ARCHITECTURES) set(... 120a CACHE ...)`——**默认值就是 120a，连 flag 都不用传**（docs/01 的 `=89` 是作者为其 Ada 卡显式传入）。工程量从"flag 级"再降为"零改动"。
2. **"写错 arch 会静默降级"不成立（CODE 第四轮小澄清）**：基线 L11-13 有白名单 `if(NOT CMAKE_CUDA_ARCHITECTURES MATCHES "^(120a|89)$")` → 显式报错拒配。防呆是硬的。
3. **"实际是显式参数化，非自动定容"过于绝对**：`kv_capacity.cpp` 的 `automatic_headroom_bytes` + `resolve_kv_capacity` 是 **Device KV 池自动解析**代码路径；Host KV 确为显式 MiB 参数。准确表述："Device 侧有自动解析代码、Host 侧显式参数化；v1.0.8 CLI 实际暴露哪些开关 M4 `--help` 定"。
4. **"论文 PDF 当前环境无法文本解析"是错误陈述**：TELE 全程用 pdfplumber 成功提取 12 页全文（本会话第一轮）。真实原因 = **论文本来就没写 PPL 语料口径**（§5.3 只有数值口径），不是读不到。候选 C 结论不变、论据修正。

另两处笔误级：报告 L9 魔搭 URL 少 `ninfer-` 前缀（实际执行命令 URL 正确，仅目录名少前缀）；"40 个 changed-files 头注释"TELE 数为 43 处（搜索模式差异，无关紧要）。
